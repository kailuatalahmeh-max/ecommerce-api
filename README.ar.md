# 🛒 متجر إلكتروني — Backend API

[English](README.md) | **العربية**

باك إند لمتجر إلكتروني مبني باستخدام **Express.js** و **MongoDB**، ويدعم:

- إدارة المنتجات مع إمكانية إضافة عدة صور للمنتج الواحد.
- سلة مشتريات بدون الحاجة لتسجيل الدخول باستخدام `Guest ID`.
- إنشاء وإدارة الطلبات.
- تأكيد الطلب عبر واتساب برمز يُستخدم مرة واحدة (التأكيد يدوي حالياً).
- متابعة الطلبات برمز التأكيد + رقم الهاتف (طلب واحد، أو عدة طلبات مرة واحدة).
- لوحة تحكم إدارية مع نظام صلاحيات متعدد المستويات، وإمكانية تفعيل وتعطيل حسابات الأدمن.
- حماية الـ API من إساءة الاستخدام والتحقق من المدخلات.
- معالجة تعارضات المخزون أثناء عمليات الشراء.
- اختبارات تكامل ووحدة باستخدام Jest و Supertest.

> 💡 هذا أول مشروع Backend حقيقي لي. بنيته بعد حوالي شهر ونصف من تعلم Express.js و MongoDB.

> هذا الملف يخص الـ Backend فقط. الـ Frontend موجود في مستودع منفصل: [ecommerce-frontend](https://github.com/kailuatalahmeh-max/ecommerce-frontend/blob/main/README.ar.md).

> 📖 التفاصيل (الـ API، الطلبات، النماذج، الحماية، السكربتات، الاختبارات) موجودة في مجلد [`docs/`](#-التوثيق).

## 🧰 التقنيات المستخدمة

| التقنية                  | الاستخدام                                  |
| ------------------------ | ------------------------------------------ |
| **Node.js + Express.js** | بناء السيرفر والـ API                      |
| **MongoDB + Mongoose**   | قاعدة البيانات وإدارة الـ Models           |
| **JWT (jsonwebtoken)**   | مصادقة الأدمن                              |
| **bcrypt**               | تشفير كلمات المرور                         |
| **express-rate-limit**   | حماية الـ endpoints من إساءة الاستخدام     |
| **cors**                 | التعامل مع الطلبات القادمة من الـ Frontend |
| **dotenv**               | قراءة متغيرات البيئة من ملفات `.env`       |
| **crypto**               | توليد رموز تأكيد عشوائية للطلبات           |
| **Jest + Supertest**     | اختبارات الـ API                           |

## 📁 هيكل المشروع (Backend)

```text
backend/
├── .env.example          # مثال لمتغيرات البيئة (انسخه إلى .env)
├── docs/                 # التوثيق المفصّل (إنجليزي)، docs/ar/ (عربي)
├── myApp.js              # تعريف تطبيق Express (الـ middlewares والمسارات) — تستورده الاختبارات
├── server.js             # نقطة التشغيل: الاتصال بقاعدة البيانات، تشغيل السيرفر ومهمة الطلبات المنتهية
├── backups/              # نسخ احتياطية JSON من seedPhoneShop.js (غير موجودة في git)
├── scripts/              # سكربتات صيانة وترحيل بيانات وبيانات تجريبية (تُشغَّل يدوياً)
├── src/
│   ├── config/           # الاتصال بقاعدة البيانات
│   ├── controllers/      # منطق العمليات
│   ├── middlewares/      # المصادقة، الصلاحيات، التحقق، Rate Limiting، معالجة الأخطاء، فحص واتساب المتجر
│   ├── models/           # Admin, Cart, Item, Order, StoreSettings
│   ├── routes/           # تعريف المسارات
│   ├── services/         # orderConfirmation (رمز تأكيد واتساب)، stock (إرجاع / أخذ المخزون)، expireOrders (مهمة الطلبات المنتهية)
│   └── utils/            # ثوابت مشتركة (constants.js)، تنظيف رقم الهاتف (phone.js)، عدد الـ proxies (trustProxy.js)
└── tests/
    ├── setup/            # الاتصال بقاعدة بيانات الاختبار
    ├── fixtures/         # بيانات جاهزة للاختبارات
    ├── helpers/          # دوال مساعدة (إنشاء أدمن تجريبي، إضافة منتج...)
    ├── integration/      # اختبارات الـ endpoints
    └── unit/             # اختبارات الوحدة
```

تم فصل `myApp.js` عن `server.js` حتى تتمكن الاختبارات من استيراد التطبيق وتشغيله بدون فتح منفذ أو الاتصال بقاعدة البيانات الرئيسية.

## ⚙️ الإعداد والتشغيل

جميع الأوامر التالية تُنفَّذ من داخل مجلد `backend/`.

### 1. تثبيت الحزم

```bash
cd backend
npm install
```

### 2. إعداد متغيرات البيئة

انسخ ملف المثال، ثم ضع قيمك الخاصة (**داخل مجلد `backend/`**):

```bash
cp .env.example .env
```

ملف `.env.example` فيه كل المتغيرات مع ملاحظة قصيرة (لا يحتوي أسراراً حقيقية، لذلك هو في git). ملف `.env` الحقيقي لا يُرفع أبداً. المتغيرات:

| المتغير        | مطلوب | ملاحظات                                                      |
| -------------- | ----- | ------------------------------------------------------------ |
| `MONGO_URI`    | نعم   | رابط الاتصال بـ MongoDB                                      |
| `JWT_SECRET`   | نعم   | المفتاح السري لتوقيع توكنات الأدمن                           |
| `FRONTEND_URL` | نعم   | الـ origin الوحيد المسموح في CORS (عنوان الـ Frontend)        |
| `PORT`         | لا    | الافتراضي `5000`                                             |
| `MONGO_URI2`   | لا    | فقط لـ `scripts/seedPhoneShop.js` و`scripts/updateAdminsLastActivity.js`. السيرفر لا يستخدمه |
| `WHATSAPP_BOT_ENABLED` | لا | القيمة `true` تضيف مسار البوت `GET /api/orders/:id/confirmation`. اتركه فارغاً حالياً |
| `TRUST_PROXY`  | لا    | عدد الـ proxies أمام التطبيق. الافتراضي `1`. **على Render ضع `2`** (Cloudflare + الـ load balancer). راجع [الحماية](docs/ar/security.md#-عنوان-ip-الحقيقي-للزبون-trust_proxy) |

عند تشغيل السيرفر (`server.js`) يتم التحقق من `MONGO_URI` و`JWT_SECRET` و`FRONTEND_URL`. إذا كان أحدها مفقوداً، يطبع `Missing environment variables: ...` ويتوقف.

### 3. تشغيل السيرفر

```bash
npm start
```

أو للتطوير مع إعادة التشغيل التلقائية عند تعديل الملفات (nodemon):

```bash
npm run dev
```

يبدأ السيرفر بالاتصال بقاعدة البيانات، وإذا فشل الاتصال يتوقف التشغيل مباشرة. بعد نجاحه يعمل افتراضياً على:

```text
http://localhost:5000
```

### 4. التأكد من أن السيرفر يعمل

```http
GET /health
```

الاستجابة:

```json
{
  "status": "ok"
}
```

> ملاحظة: الـ `/health` endpoint محمي أيضاً باستخدام Rate Limiting، وهو خارج المسار `/api`.
