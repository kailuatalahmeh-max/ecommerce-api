# 🧪 الاختبارات

```bash
npm test
```

يتم تشغيل الاختبارات عبر `jest --runInBand` (ملف بعد ملف). التشغيل المتوازي (`npx jest`) يعمل أيضاً، لأن كل ملف له قاعدة بيانات خاصة.

### قاعدة بيانات الاختبار (في الذاكرة)

الاختبارات تستخدم **[mongodb-memory-server](https://github.com/typegoose/mongodb-memory-server)**: قاعدة MongoDB حقيقية تعمل **في الذاكرة** على جهازك. بدون Atlas، وبدون إنترنت، وبدون قائمة IP.

- كل ملف اختبار يشغّل قاعدة فارغة خاصة به (`testingDataBase`) ويحذفها عندما ينتهي (`tests/setup/db.js`).
- الاختبارات لا يمكن أن تلمس قاعدة حقيقية: تتوقف إذا لم يكن العنوان `127.0.0.1`.
- **أول تشغيل** يحمّل ملف MongoDB مرة واحدة (حوالي 1–2 دقيقة). بعدها يُحفظ، وكل الاختبارات تأخذ ثوانٍ قليلة.
- ملف `.env.testing` **اختياري**. يعطي `JWT_SECRET` فقط (`MONGO_URI` لا يُستخدم). بدونه تستخدم الاختبارات `"test-secret"`.

> MongoDB driver 7 يحمّل `os` باستخدام `import()` ديناميكي، و Jest يمنع ذلك، فيرفض السيرفر الاتصال ("Missing required sub-document 'driver'"). ملف `db.js` يحل المشكلة بإعطاء الـ driver الـ `os` مباشرة: `mongoose.connect(uri, { runtimeAdapters: { os } })`.

### ما الذي تغطيه الاختبارات؟

- **`items.test.js`**: جلب المنتجات، الإضافة والتعديل بواسطة أدمن، رفض التوكن المفقود أو غير الصالح، رفض الأدمن المعطّل، رفض البيانات غير الصالحة (سعر سالب، روابط `javascript:`)، والمعرّفات غير الصالحة أو غير الموجودة

**`orders.test.js`**

- الشراء المباشر: النجاح يحدّث المخزون والإجمالي؛ رفض المعرّف غير الصالح، الكمية غير الصالحة، الكمية الأكبر من المخزون، والمنتج غير الموجود
- **تعارض المخزون:** طلبان متزامنان على مخزون يكفي لطلب واحد ← واحد `201` وواحد `400`، ويُحفظ طلب `1` فقط
- **تأكيد واتساب:** الشراء يرجع رمزاً ورابط `wa.me`؛ `503` بدون رقم المتجر؛ `GET /:id/confirmation` يرجع `404` والبوت متوقف؛ المشرف يؤكد مرة واحدة فقط (`409` في المرة الثانية)؛ رقم خاطئ ← `PHONE_MISMATCH`؛ صلاحية `admin` ← `403`
- **التتبّع:** `/track` ينظّف الرمز والرقم، ويرفض الكائنات (injection) والرقم الخاطئ؛ `/track-many` يرجع `found` / `notFound` / `invalid` بالترتيب، ولا يعرض طلبات أخرى لنفس الرقم، ويرفض القائمة الفارغة أو الطويلة (أكثر من 20)؛ والمسار القديم `/api/guest/sessions` يرجع `404`
- **الإلغاء:** `/cancel` يلغي طلب `Pending` مرة واحدة ويرجع المخزون (الضغطة الثانية ← `409`، والمخزون لا يرجع مرتين)؛ يرفض الرقم الخاطئ (`404`) والـ injection (`400`) والطلب `Accepted` (`409`)؛ الطلب الملغي لا يمكن تأكيده (`CANCELLED`)
- **حالة الأدمن:** إلغاء الأدمن يرجع المخزون مرة واحدة (`cancelledBy: "admin"`)؛ إعادة فتح الطلب تأخذ المخزون مرة أخرى، أو تُرفض بـ `NOT_ENOUGH_STOCK`؛ تغيير الحالات الأخرى لا يحرّك المخزون؛ الزبون لا يستطيع إلغاء طلب ألغاه الأدمن
- **المنتهية:** الطلب `Pending` المنتهي يصبح `Cancelled` (`cancelledBy: "system"`) ومخزونه يرجع مرة واحدة فقط؛ الطلبات الجديدة والمؤكدة والمقبولة لا تتأثر؛ الطلب الذي ألغاه الزبون لا يرجع مخزونه مرتين

- **`auth.test.js`**: مسارات الأدمن ترجع `401` بدون توكن، أو بتوكن مزيّف، أو بتوكن صحيح لأدمن غير موجود

- **`health.test.js`**: `GET /health` يرجع `200`

- **`cart.test.js`**: إضافة نفس المنتج مرتين تجمع الكمية في **سطر واحد** في السلة (2 + 3 = 5)، والإضافة للسلة لا تُنقص المخزون

- **`storeSettings.test.js`**: `super_admin` يحفظ رقماً فيه مسافات فيُحفظ نظيفاً (`+970599111222`)، ومستند إعدادات واحد فقط؛ `GET` يرجع `null` بدون رقم؛ الرقم الخاطئ أو الفارغ أو الكائن أو كود دولة غير مدعوم ← `400` `INVALID_PHONE` والرقم القديم يبقى؛ `admin` و`moderator` ← `403`، وبدون توكن ← `401`؛ `GET /public` يعمل بدون توكن ويرجع `whatsappNumber` **فقط**

- **`unit/trustProxy.test.js`**: `TRUST_PROXY` يقرأ `0`–`10`، والقيمة المفقودة أو الخاطئة تعطي `1`؛ مع `2` (Cloudflare + Render) يكون `req.ip` هو IP الزبون الحقيقي ولا يستطيع `X-Forwarded-For` مزيّف تغييره؛ مع `1` يكون IP تابعاً لـ Cloudflare
