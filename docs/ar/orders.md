# 💬 تأكيد الطلب عبر واتساب

كل طلب جديد يجب أن يؤكده الزبون على واتساب. هذا يثبت أن الزبون يملك رقم الهاتف فعلاً.

1. الزبون يشتري (مباشر أو من السلة). يُحفظ الطلب مع `confirmation.status: "pending"` ورمز من 6 خانات.
2. مسارا الشراء يرجعان:

```json
{
  "data": {
    "orderId": "...",
    "confirmCode": "K7P2XM",
    "expiresAt": "2026-11-23T15:35:00.000Z",
    "whatsappUrl": "https://wa.me/970599123456?text=..."
  }
}
```

3. `whatsappUrl` يفتح محادثة مع رقم المتجر، والرسالة مكتوبة جاهزة:

```text
تأكيد طلب
رمز التأكيد: K7P2XM
```

4. المشرف يؤكد الطلب يدوياً بعد رؤية الرسالة (`POST /api/orders/confirm`).
5. الزبون يستطيع رؤية الطلب وحالة تأكيده بالرمز (`POST /api/orders/track`، انظر بالأسفل) أو من صفحة "طلباتي".

> 🚧 المسار `GET /api/orders/:id/confirmation` لبوت واتساب المستقبلي. يُضاف **فقط** عندما `WHATSAPP_BOT_ENABLED=true`، ويحتاج صلاحية `bot`. يرجع `pending` أو `confirmed` أو `expired` (الطلب `pending` بعد `expiresAt` يظهر `expired`؛ الطلبات القديمة بدون `confirmation` ترجع `confirmed`). الـ Frontend لا يستخدمه.

### تتبّع الطلب (`POST /api/orders/track`)

```json
{ "code": "K7P2XM", "phoneNumber": "+970599123456" }
```

الزبون يحتاج **الاثنين معاً**: الرمز ورقم الهاتف. الـ middleware `validateTrackOrder.js` يفحصهما قبل قاعدة البيانات:

- الاثنان يجب أن يكونا نصاً. الكائنات مثل `{ "$ne": null }` تُرفض (NoSQL injection).
- `code`: تُحذف المسافات وتصبح الحروف كبيرة (`k7p 2xm` ← `K7P2XM`). بعدها يجب أن يكون 6 خانات من حروف رمز التأكيد (بدون `0 O 1 I L`).
- `phoneNumber`: يُنظَّف بـ `normalizePhone`، مثل صفحة الشراء (`+970 0599-123-456` ← `+970599123456`).
- القيم النظيفة تصل للـ controller في `res.locals.tracking`.
- حد الطلبات: **20**.

| الحالة                                        | الكود |
| --------------------------------------------- | ----- |
| تم العثور عليه (`data` هو الطلب كاملاً)        | `200` |
| الرمز أو الرقم مفقود أو ليس نصاً              | `400` |
| شكل الرمز غير صحيح                            | `400` |
| رقم الهاتف غير صحيح                           | `400` |
| لا يوجد طلب بهذا الرمز **وهذا** الرقم          | `404` |

> الرقم يجب أن يطابق تماماً: الطلب المحفوظ بـ `+970` لا يُوجد بـ `+972` (التأكيد اليدوي يعتبرهما نفس الرقم، التتبّع لا).

### تتبّع عدة طلبات (`POST /api/orders/track-many`)

تستخدمه صفحة "طلباتي": المتصفح يحفظ `{ code, phoneNumber }` لكل طلب، ويطلب بيانات جديدة لها كلها في طلب **واحد** (استعلام واحد لقاعدة البيانات).

```json
{
  "orders": [
    { "code": "K7P2XM", "phoneNumber": "+970599123456" },
    { "code": "ABCDEF", "phoneNumber": "+970599123456" },
    { "code": "bad", "phoneNumber": "+970599123456" }
  ]
}
```

الرد (بنفس الترتيب والطول):

```json
{
  "success": true,
  "data": [
    { "code": "K7P2XM", "phoneNumber": "+970599123456", "status": "found", "order": { "...": "..." } },
    { "code": "ABCDEF", "phoneNumber": "+970599123456", "status": "notFound" },
    { "code": "bad", "phoneNumber": "+970599123456", "status": "invalid" }
  ]
}
```

- `orders` يجب أن تكون مصفوفة فيها **من 1 إلى 20** عنصر، وإلا يُرفض الطلب كله بـ `400`.
- كل عنصر يُفحص بنفس قواعد `/track` (`validateTrackMany` في `validateTrackOrder.js`).
- العنصر الخاطئ **لا** يرفض الطلب. يرجع `"invalid"`، حتى لا يخفي طلبٌ محفوظ تالف باقي الطلبات.
- `code` و`phoneNumber` في الرد هما ما أرسله المتصفح، ليطابق كل رد مع طلبه المحفوظ.
- لا يعرض أبداً طلبات أخرى لنفس الرقم: فقط الطلبات التي ترسل رمزها.
- حد الطلبات: **60**.

### إلغاء الزبون للطلب (`POST /api/orders/cancel`)

يستخدمه زر **إلغاء الطلب** في صفحة "طلباتي".

```json
{ "code": "K7P2XM", "phoneNumber": "+970599123456" }
```

- الرمز والرقم يُفحصان بنفس قواعد `/track` (`validateTrackOrder`).
- يمكن إلغاء الطلب **`Pending`** فقط (المتجر لم يقبله بعد).
- الطلب يصبح `Cancelled`، مع `cancelledAt` و`cancelledBy: "customer"`.
- **المخزون يرجع**: كل منتج يأخذ كميته مرة أخرى. المنتج المحذوف يُتجاوز.
- تحديث واحد atomic (`findOneAndUpdate` مع `status: "Pending"`). لذلك ضغطتان بنفس اللحظة ترجعان المخزون مرة واحدة فقط.
- الطلب الملغي لا يمكن تأكيده بعد ذلك (`CANCELLED` في جدول التأكيد اليدوي).
- حد الطلبات: **20**.

| الحالة                              | الكود | `code` في الرد       |
| ----------------------------------- | ----- | -------------------- |
| تم الإلغاء (الرد فيه الطلب)         | `200` | —                    |
| رمز أو رقم غير صحيح                 | `400` | —                    |
| لا يوجد طلب بهذا الرمز + الرقم      | `404` | —                    |
| مقبول، أو تم توصيله، أو ملغي مسبقاً | `409` | `NOT_CANCELLABLE`    |

> **تغيير الأدمن لحالة الطلب** (`PATCH /api/orders/:orderId`) يحرّك المخزون أيضاً:
> - إلى `Cancelled`: المخزون يرجع، والطلب يحفظ `cancelledBy: "admin"`.
> - من `Cancelled` (إعادة فتح الطلب): المخزون يُؤخذ مرة أخرى، ويُحذف `cancelledAt` / `cancelledBy`. إذا منتج واحد مخزونه غير كافٍ (أو محذوف)، لا يتغير شيء والرد `400` `NOT_ENOUGH_STOCK`.
> - بين الحالات الأخرى (`Pending` / `Accepted` / `Delivered`): المخزون لا يتغير.
> - التحديث يعمل فقط إذا لم تتغير الحالة في نفس الوقت، لذلك ضغطتان تحرّكان المخزون مرة واحدة فقط. غير ذلك: `409` `STATUS_CHANGED`.

### ⏳ الطلبات المنتهية (المخزون يرجع)

الطلب الذي **لم يُؤكَّد على واتساب خلال 24 ساعة** يلغيه السيرفر (`src/services/expireOrders.service.js`):

- `server.js` يشغّل المهمة بعد الاتصال بقاعدة البيانات. تعمل **مرة عند التشغيل** (لتلحق ما فات إذا كان السيرفر نائماً)، ثم **كل 10 دقائق**. الاختبارات لا تشغّلها.
- تبحث عن الطلبات التي فيها `status: "Pending"` و`confirmation.status: "pending"` و`confirmation.expiresAt` في الماضي (الـ index على `confirmation.status` + `confirmation.expiresAt` يجعل البحث سريعاً).
- كل طلب يصبح `status: "Cancelled"` و`confirmation.status: "expired"` و`cancelledBy: "system"`، و**مخزونه يرجع** (`returnStock` في `src/services/stock.service.js`).
- تحديث atomic واحد لكل طلب، لذلك المخزون يرجع مرة واحدة فقط (حتى لو ألغى الزبون في نفس اللحظة).
- **لا تتأثر:** الطلبات المؤكدة، والطلبات التي قبلها الأدمن.
- الأدمن يستطيع إعادة فتح طلب منتهي: المخزون يُؤخذ مرة أخرى، أو يُرفض التغيير بـ `NOT_ENOUGH_STOCK`.

### التأكيد اليدوي (`POST /api/orders/confirm`)

```json
{ "code": "K7P2XM", "senderPhone": "+970599123456" }
```

- `senderPhone` يجب أن يكون رقم الطلب. `+970` و`+972` يُعتبران نفس الرقم (`isSamePhone` في `src/utils/phone.js`).
- التحديث يعمل فقط إذا كان الطلب ما زال `pending` ولم تنتهِ صلاحيته. لذلك إذا أكّد شخصان بنفس اللحظة، ينجح واحد فقط.
- نفس الدالة (`confirmOrderByCode` في `src/services/orderConfirmation.service.js`) جاهزة لبوت واتساب لاحقاً.

| الحالة                         | الكود | `code` في الرد       |
| ------------------------------ | ----- | -------------------- |
| تم التأكيد                     | `200` | —                    |
| شكل الرمز غير صحيح             | `400` | `INVALID_CODE`       |
| الرقم ليس رقم الطلب            | `400` | `PHONE_MISMATCH`     |
| لا يوجد طلب بهذا الرمز         | `404` | `NOT_FOUND`          |
| مؤكد مسبقاً                    | `409` | `ALREADY_CONFIRMED`  |
| الزبون ألغى الطلب              | `409` | `CANCELLED`          |
| مرّ أكثر من 24 ساعة            | `410` | `EXPIRED`            |
